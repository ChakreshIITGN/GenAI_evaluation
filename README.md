# RB GenAI Evaluation

Author: Dr. Chakresh Kr. Singh. Prepared for Roland Berger.

## What this repository does

A Beauty & Wellbeing company built LLM-based simulations of individual
consumers from a first interview, following Park et al. (arXiv:2411.10109).
This repository evaluates how faithfully those simulations mimic the real
people's open-ended answers, as a risk control: it tells the business where
the simulations can be trusted for decisions and where they cannot.

Data: 3 people x 10 questions; for every question one pair, the real human
answer and the simulation's answer (30 pairs). The data file is confidential
and gitignored; it is delivered separately (see Confidentiality below).

The evaluation asks three plain questions, each answered by one measurement
layer:

| Question | Layer | How |
|---|---|---|
| Could a blind reader tell it is AI? | Style features + blind judge panel | 7 deterministic features; blind believability reading |
| Does it say what this person said? | NLI content checks | every sentence checked both directions (coverage / fidelity) |
| Is it this person, or a generic consumer? | Judge panel with persona sketch | individuation score, agreement measured |

## Design principles

- Deterministic and cheap first; LLM judgement only where deterministic
  methods cannot answer.
- Judges return only booleans or bounded scores plus a one-line reason;
  every percentage, count, and KPI is computed in tested Python code.
- All prompts live in `user_prompts/` (one plain-text file per use), never
  in code.
- Every LLM call goes through `src/llm.py`: temperature 0, fixed seed, JSON
  enforced, Pydantic-validated with one retry-with-repair, disk-cached under
  `cache/` so runs resume and reproduce.
- Honest reporting: failed or degenerate measurements are reported as such
  (see KPI 2), corrections are archived and documented, decisions are logged.

## Glossary

- **Pair**: one question's real human answer plus the simulation's answer.
- **Held-out split**: fixed and explainable; questions 7 to 10 are judged
  for every person, the person's other questions serve as context. Set in
  `config.yaml` (`eda.held_out_questions`).
- **EDA Q0 / Q1 / Q2**: zero-shot "is this AI?" on every answer; "does the
  AI capture this person's personality?" given the person's own answers;
  "does the AI capture the content?" pairwise. Q1/Q2 are reported as raw
  yes-counts, never percentages.
- **Coverage**: share of the human answer's sentences that the simulation's
  answer entails (completeness: did it keep what the person said?).
- **Fidelity**: share of the simulation's sentences that the human answer
  entails (accuracy: is what it says backed by the person?). Both come from
  a deterministic local NLI model, not from judges.
- **Contradiction**: an AI sentence the NLI model labels as the opposite of
  the human answer; more dangerous than merely unsupported.
- **Blind spot / phantom / covered**: topic-level vocabulary (Layer 2c);
  a theme only the humans discuss / only the AI discusses / both discuss.
- **Individuation**: judge score from -1 (generic segment member) to +1
  (recognisably this person), judged against a persona sketch built from
  the person's other answers.
- **Blind discrimination rate**: how often a judge's believability score has
  the right sign, computed by us against the known labels; 0.5 = cannot tell.
- **Krippendorff's alpha**: chance-corrected agreement among the three
  judges on identical items; 1 = perfect, 0 = chance level. Reported per
  construct as the reliability tag.
- **Judge panel**: three LLM judges from different model families
  (gpt-oss:120b, deepseek-v4-flash, glm-5.2), all scoring the same items.
- **RAG matrix**: green / amber / red per person (pooled over categories;
  category slices are too small in this data), driven by the harmonic mean
  of coverage and fidelity; thresholds in `config.yaml`, provisional at n=30.
- **Cache**: every LLM reply stored on disk keyed on (model, prompt); an
  interrupted run resumes free, a finished run reproduces without API keys.

## Reproduce everything, end to end

Prerequisites: Python 3.13, [uv](https://docs.astral.sh/uv/), an
[Ollama cloud](https://ollama.com) account with a free API key, and the
confidential data file.

```bash
# 1. Setup
git clone https://github.com/ChakreshIITGN/GenAI_evaluation.git
cd GenAI_evaluation
git checkout eval                       # the full pipeline branch
uv sync                                 # installs all pinned dependencies
uv run python -m spacy download en_core_web_sm

# 2. Secrets and data (both gitignored, never commit them)
cp .env.example .env                    # put your Ollama cloud key in .env
mkdir -p data                           # place RB_GenAI_Datatest.xlsx here

# 3. Verify the machinery (fast, no network, no key needed)
uv run pytest

# 4. Optional: check which cloud models your plan can run
uv run python scripts/check_models.py

# 5. The EDA (LLM calls, cached under cache/)
uv run python run_eda.py

# 6. The full pipeline: NLI, topics, judge panel, KPIs
#    First run downloads the local NLI + embedding models (~1 GB)
uv run python run_all.py

# 7. All figures (no LLM)
uv run python run_plots.py
uv run python scripts/run_topics.py     # topic map + sentence map only
```

What you get in `output/`: `eda_*.csv` (verdicts, metrics, verbatim judge
reasons), `pairs_content.csv` (coverage/fidelity per pair),
`kpi1_content_fidelity.csv`, `rag_matrix.csv`, `kpi3_believability.csv`,
`ratings_*.csv` (judge scores + reasons), `topics.csv`, `run_*manifest.json`
(models, seeds, config echo, timings), and `plots/*.png` (all figures,
Roland Berger palette).

Reproducibility notes:
- Every LLM reply is cached: rerunning any entrypoint is free and identical.
  Delete or move `cache/` to force fresh calls.
- Deterministic layers (style, NLI, topics) are seeded via `config.yaml`.
- If a run dies mid-way (quota, network), just rerun it: completed calls are
  served from cache and the run continues where it stopped.
- A sentence-level audit of the NLI calls is available:
  `uv run python scripts/spot_check_nli.py <person_id> <question_id>`.

## Confidentiality

The repository is public for evaluators. The interview data and everything
that embeds it (the data file, the LLM cache, run outputs, archives) are
gitignored and delivered separately as a private zip. Drop the zip's `data/`,
`cache/`, and `output/` folders into the repo root and every number and
figure regenerates without any API key.
